# Local Development

Use Node 22.22 (the Docker build version) or the developer/CI version in
[`.tool-versions`](https://github.com/egose/k8ston/blob/main/.tool-versions),
the pnpm version selected by root `package.json`, and a kubeconfig for a development
cluster (`KUBECONFIG` or `~/.kube/config`). Current dependencies require at least Node 22.19.
Choose credentials allowed to manage Secrets in your development namespace.

## Mock-admin loop (no IdP)

```bash
# From the repository root.
pnpm install --frozen-lockfile
cp -n app/.env.example app/.env
# Set K8STON_NAMESPACE in app/.env to your development namespace (example: default).
pnpm --dir app dev --hostname 127.0.0.1   # http://localhost:3000
```

`cp -n` preserves an existing `app/.env`; adapt it deliberately if it exists.
`AUTH_DISABLED=true` signs every request in as the mock admin `dev@k8ston.local`
and ignores session cookies. It still performs real Kubernetes writes, so use a
development cluster, keep it loopback-bound, and never enable it in production
or for per-user authorization checks. Managed-only mode hides unmanaged Secrets by default.

## Real-SSO loop (local app, real IdP)

Set a fresh random `SESSION_SECRET` (use `openssl rand -hex 32`),
`AUTH_DISABLED=false`, and your `OIDC_*` settings in `app/.env`. Your IdP needs
the redirect URI registered:

```text
http://localhost:3000/api/auth/callback
```

`OIDC_ISSUER` is the issuer identifier, **not** the discovery URL: the app
appends `/.well-known/openid-configuration` itself, and it must exactly match
the `issuer` field of that document (Keycloak realms often live under
`/auth/realms/...`).

Note: OIDC configuration is cached per process — restart `pnpm dev` if you
change issuer settings or restart your IdP.

## Prefer batteries-included?

The repo-root [sandbox](/guides/sandbox/) spins up a kind cluster with seeded
fixtures plus Dex as a throwaway OIDC provider (`make up`, then copy
`sandbox/app.env.sandbox` to `app/.env`). Use it when you want realistic SSO,
authz fixtures, and consumer workloads without touching a shared cluster.

## Commands

Run these from the repository root:

| Command                                           | Purpose                                            |
| ------------------------------------------------- | -------------------------------------------------- |
| `pnpm --dir app dev --hostname 127.0.0.1`         | Loopback dev server with hot reload                |
| `pnpm --dir app build`                            | Production build                                   |
| `pnpm --dir app start --hostname 127.0.0.1`       | Serve the production build on loopback             |
| `pnpm --dir app lint`                             | ESLint                                             |
| `pnpm --dir app e2e`                              | Playwright browser suite; needs a production build |
| `pnpm --dir app exec playwright install chromium` | One-time browser install                           |
| `pnpm test:unit`                                  | Backend regressions; no cluster or IdP required    |

Browser tests mock Kubernetes-backed HTTP APIs; they are not proof of real cluster
RBAC or end-to-end OIDC. See the sandbox for integration checks.

:::note
The host dev server uses your selected kubeconfig — it does **not** exercise
`app/k8s/role.yaml` or the ServiceAccount-token flow. Validate those against
kind too; the [sandbox guide](/guides/sandbox/) shows how.
:::
