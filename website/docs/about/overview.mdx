# Overview

K8ston is a lightweight secret manager UI and API backed **directly by Kubernetes Secret objects**.
No database, no persistent volumes, no secret sprawl: Kubernetes is the source of
truth, and K8ston is the translation + visualization layer on top.

It is built with Next.js (App Router), `@kubernetes/client-node`, generic OIDC SSO, and
shadcn-theme components.

## How it works

```text
Browser ──SSO login──▶ K8ston (Next.js)
                            │  ServiceAccount token (auto-mounted in-cluster)
                            │  https://kubernetes.default.svc  — no credentials to manage
                            ▼
                    Kubernetes API ──▶ etcd (Secrets + one access ConfigMap)
```

- **State**: every secret is a native `Secret` object. Standard tools (Velero,
  `kubectl`, GitOps) keep working; cluster RBAC, audit configuration, and network
  controls remain the operator's responsibility.
- **Auth**: users sign in through OIDC-compatible providers such as Keycloak or Dex.
  OAuth-only providers need an OIDC-compatible bridge. In the default hybrid mode,
  users do **not** need Kubernetes identities or cluster credentials.
- **Authz (hybrid)**: SSO proves _who you are_; per-secret annotations and one
  namespace-level ConfigMap decide _what you may see_. The app's ServiceAccount
  executes the K8s calls.
- **History**: K8s overwrites secrets in place, so K8ston snapshots the previous
  state into an immutable, UID/resourceVersion-bound Secret before updates and
  restores. Rollbacks preserve raw bytes and current access rules within the
  [retained history](/guides/versioning-history/).

## What K8ston is not

- **Not an encryption layer.** Out of the box, Kubernetes Secrets are **base64-encoded,
  not encrypted**, in etcd. K8ston shows a warning banner until you confirm etcd
  encryption-at-rest is enabled (`K8STON_ETCD_ENCRYPTED=true`). Read the
  [Security Model](/about/security-model/) before production.
- **Not a replacement for RBAC.** K8ston adds an SSO-friendly authorization layer
  for users without cluster identities. The ServiceAccount it runs as should still
  follow least privilege (namespace `Role` by default, `ClusterRole` only for
  multi-namespace dashboards).
- **Not a secret generator or rotation engine.** It stores, versions, and gates
  access to values your teams already manage.

## At a glance

| Concern          | Approach                                                                                |
| ---------------- | --------------------------------------------------------------------------------------- |
| Storage          | Native `Secret` objects; snapshots labeled `k8ston.io/kind=history`                     |
| Login            | Generic OIDC (discovery-based), stateless HS256 session JWT                             |
| Authorization    | Admins bypass; per-secret annotations override namespace fallback                       |
| Concurrency      | Optimistic writes on `metadata.resourceVersion` (409 + reload on drift)                 |
| Size guard       | 1 MiB data guard in the form and API; validation/payload failures return 400/413        |
| Consumer rollout | Opt-in bounded rollout requests for explicit Secret consumers; reports partial failures |
| Deployment       | Raw manifests (`app/k8s/`) or Helm (`helm/main` + `helm/k8ston` subchart)               |
